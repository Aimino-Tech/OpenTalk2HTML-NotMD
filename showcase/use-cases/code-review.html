Summary

This PR refactors the authentication middleware to use a strategy pattern, replacing the monolithic auth handler with composable authentication strategies (JWT, OAuth2, API Key). The change improves testability, reduces code duplication, and prepares the system for SAML/SSO support.

// After: Strategy pattern
const strategies = new StrategyRegistry();
strategies.register('jwt', new JwtStrategy(config.jwt));
strategies.register('oauth2', new OAuth2Strategy(config.oauth));
strategies.register('api-key', new ApiKeyStrategy(config.keys));

async function authenticate(req: Request): Promise<User> {
  const strategy = strategies.get(req.authType);
  return strategy.validate(req);
}

Review Notes

🚫 Missing rate limiting on OAuth2 callback
The OAuth2 callback handler lacks rate limiting, which could allow token replay attacks. Consider adding a rate limiter middleware.
⚠️ JWT secret should be rotated
The JWT signing key appears to be the default development key. Ensure a production key is configured via environment variable.
ℹ️ Consider adding refresh token support
The current JWT strategy uses short-lived tokens (15 min) but doesn't implement refresh tokens. Consider adding refresh token rotation for better UX.
